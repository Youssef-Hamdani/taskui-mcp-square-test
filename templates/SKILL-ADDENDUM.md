# TaskUI assistant workflow (v1)
This is adaptive UX guidance, not an OpenAI rendering protocol. Native intelligent UI is preferred when available. Ordinary conversational review is the functional fallback. The optional widget owns its entire state; do not nest it into native forms or invent a shared bridge.

1. Call get_taskui_configuration; show simulation/connected mode truthfully. For real work call list_projects/load_project and use the returned snapshot as the source. Never guess a spreadsheet or rely on old UI state.
2. Build a full canonical draft. Generate UUIDs for project/task/draft IDs once; preserve IDs while switching creation modes. Translate name/id/estimated_min to title/task_id/estimated_minutes with explicit adapter. Prefill only known facts. Unknown estimates/dates/costs stay null. AI suggestions have AI provenance. Frameworks allow pragmatic grouping, not claimed scheduling engines.
3. Show editable project details and task rows, constraints/budgets in context, optional grounded costs, dependencies and instruction scope. Manual/AI/hybrid changes do not replace entered values. Keep a reset snapshot and practical undo. Invalid edits remain editable. Submit the COMPLETE JSON as a new conversation turn; a minimal event cannot recover UI state.
4. Call validate_project_draft and preview_project_changes. Render meaningful before/after differences, status, provenance, changed edges and immutable IDs. Color is an accent with a label/icon. For removed prerequisites show direct/transitive impacts and offer AI proposal, user-described resolution, or keeping the original. Machine validation never proves a repair makes sense in the real world.
5. For split textarea requests, propose at least two NEW child IDs, preserve parent history as Superseded, and review downstream edges explicitly. Never silently retarget. Only set edges_reviewed after showing the exact proposed changes to the user. Diagnostic outcomes required/not_required/unknown mean applicable/not_applicable/pending; unnecessary replacement is never Complete.
6. Ask explicit approval of the exact frozen digest and draft revision after displaying the validated changes. Review is not approval. Any edit invalidates the digest. Never manufacture approval. Future-project defaults cannot be saved in v1; seek separate approval in a future supported flow.
7. In connected mode only, call commit_approved_changes using that exact draft, digest, revision and unique approval ID. Retry the identical request with the same ID after an uncertain response. Verify saved readback, then load_project again before saying saved. Unauthorized/unconfigured/stale writes are failures, not local successes.
8. Manage: ready work first, blocked tasks with named reasons, known effort and unknown count, complete history and superseded/excluded history separately. Selecting a graph node must select the matching editor; editing prerequisites derives graph and blockers from the same draft. Use dependency inspector/list fallback if host interactions are unavailable. Do not claim deployment, rendering or source code proves durable save.
